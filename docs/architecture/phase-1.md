# المرحلة الأولى - الشريحة التنفيذية الأولى

## حدود المسؤولية

- الواجهة تعرض المدخلات والنتائج فقط؛ الخادم الخلفي هو مصدر حقيقة الحسابات.
- جميع الحسابات الغذائية تستخدم `Decimal` وتُقرب للعرض فقط.
- نموذج اللغة لا يشارك في حساب السعرات أو الماكروز.
- الاعتماد الطبي وإصدارات الخطط سيضافان فوق هذا المحرك دون تغيير عقود الحساب الأساسية.

## التدفق المنفذ

1. الطبيب يدخل الوزن ونسبة الدهون والجنس والنشاط والهدف.
2. الواجهة ترسل البيانات إلى `/api/v1/nutrition/calculate`.
3. المحرك يحسب LBM ثم BMR ثم TDEE والهدف اليومي.
4. المحرك يحسب الماكروز الافتراضية أو يحول نسب الطبيب إلى جرامات.
5. المحرك يتحقق من أن نسب الوجبات تساوي 100% ويوزع الأهداف.
6. الواجهة تعرض لقطة المسودة ونتائج كل وجبة.

## القرارات التالية

- ADR للمصادقة وإدارة Refresh Tokens.
- PostgreSQL + SQLAlchemy + Alembic لنماذج المستخدمين والعملاء وإصدارات الخطط.
- Health Rules للحساسية وCKD قبل توليد أي وجبة.
- Provider Adapter للذكاء الاصطناعي بعد تثبيت Food DB وValidator.
